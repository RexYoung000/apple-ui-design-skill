# Content and Sensitive-Flow Regression Suite

This suite protects the content, permission, privacy, identity, account-data, commerce, recovery, and professional-boundary method introduced for Issue #8.

It verifies that the installable plugin:

- structures consequential content around facts, choices, outcomes, and recovery;
- requests protected access in context and preserves truthful denial, limited-access, and no-access paths;
- refuses to invent collection, sharing, retention, export, deletion, price, entitlement, refund, or professional facts;
- keeps sign-in, account deletion, subscription cancellation, purchase restoration, and data operations semantically distinct;
- identifies manipulative consent and commerce patterns without turning ordinary visual emphasis into a violation;
- routes legal, medical, financial, security, privacy-policy, and regulatory conclusions to their responsible owners;
- distinguishes rendered hierarchy and app-level prototypes from native permission, service, StoreKit, policy, or professional evidence;
- uses exact current Apple pages for policy-sensitive claims.

Run:

```bash
python3 scripts/validate_content_sensitive_flow_evals.py
```

For a fresh-session check, provide only the case `prompt` and any named artifact. Do not expose `expected_behavior`, `forbidden_behavior`, or `source_markers`.

The preserved FrameKeep HTML flow establishes only the simulated app-level explanation, denial, retry, limited-selection, import failure, cancellation, and recovery paths that it exercises. It does not establish a native Photos permission prompt, real photo access, service behavior, privacy compliance, or user trust.
