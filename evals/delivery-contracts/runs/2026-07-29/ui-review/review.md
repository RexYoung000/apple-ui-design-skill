# LedgerDesk macOS 对账界面评审

## 结论

本次仅能确认 2 个由评审包直接支持的可执行问题：1 个 **Blocking**、1 个 **Important**。其余关于键盘闭环、VoiceOver、窄窗口、德语内容和撤销恢复的事项均缺少实际运行证据，作为待验证风险记录，不判定为已经失败。

这是一份基于文字化实施观察的 **UI Review 未验证咨询**，不是视觉评审、运行时体验验证或用户验收。未提出新方向或重设计。

## 评审契约与证据边界

- **主契约：** UI Review。
- **证据门槛：** 文字输入只能支持未验证咨询；不能从文字推断实际视觉、对比度、布局表现、交互完成度、原生平台适配或 VoiceOver 行为。
- **预期结果与核心任务：** 在高信任场景下，安全地把一笔到账款与正确发票匹配。
- **评审对象：** LedgerDesk 当前 Mac 对账界面；具体构建号、提交号或版本号未提供。
- **平台与输入：** macOS 14 及以上；键盘与指针为主要输入，VoiceOver 在范围内。
- **已表示的界面状态：** 发票列表、到账款列表、匹配详情三栏；已匹配行；确认匹配；移除匹配及其确认对话框。
- **已确认的产品决定：** 已匹配和未匹配项目使用克制、温暖的视觉系统，不采用默认系统蓝。
- **实际证据：** 仅有评审包中的文字化实施观察。
- **缺失证据：** 截图、对比度测量、录屏、运行中的 Mac App、VoiceOver 检查、德语布局、最小窗口测试、焦点录屏，以及明确的版本标识。
- **评审深度：** 实施观察评审；不包含视觉质量或真实体验验证。

## 严重级别汇总

| 严重级别 | 数量 | 处理优先级 |
|---|---:|---|
| Blocking | 1 | 在进入视觉/体验验收前处理 |
| Important | 1 | 与 Blocking 项一并验证 |
| Optimization | 0 | 当前证据不足，不制造润色项 |

## Findings

### 1. 已匹配状态在视觉上仅由颜色表达 — Blocking

**Observed fact：** 已匹配行只变为浅绿色，没有图标或文字状态。

**User impact：** “是否已经匹配”是确认款项与发票关系的核心数据含义。仅靠颜色会让无法可靠区分该颜色变化的用户失去这一状态线索，增加重复确认、误判匹配结果或错误移除关系的风险，与“安全、高信任”的核心结果冲突。

**Evidence or affected scenario：** macOS 对账界面的已匹配行；证据仅支持“可见呈现没有第二条非颜色线索”。评审包未提供 VoiceOver 语义，因此不能进一步声称 VoiceOver 也未表达状态，也不能判断浅绿色的实际对比度。

**Recommendation：** 保留已确认的克制暖色系统，同时为匹配状态增加至少一种可感知的非颜色表达，例如明确的状态文字、图形/形状线索；对 VoiceOver 另行提供匹配状态语义。该建议是满足已确认核心任务和可访问结果的必需项，不是要求改回系统蓝，也不规定唯一视觉方案。

**How to verify：**

1. 在真实 Mac App 中用代表性数据展示已匹配与未匹配行，保存两种状态的截图。
2. 在不依赖颜色识别的条件下，让验收者仅凭非颜色线索准确说出每一行状态。
3. 用 VoiceOver 逐行导航，确认每行的匹配/未匹配状态会被准确读出；状态变化后重新检查读出结果。
4. 对实际背景、选中态和浅绿色状态做对比度测量；在测量前不宣称对比度通过。

### 2. “确认匹配”与“移除匹配”相邻且视觉权重相同 — Important

**Observed fact：** “Confirm Match”和“Remove Match”操作相邻，并具有相同视觉权重。移除操作有确认对话框。

**User impact：** 一个操作建立财务关联，另一个移除关联；相邻且等权会削弱动作意图和后果的区分，增加用户停顿、选错操作并进入不必要确认流程的概率。确认对话框降低最终误删风险，但不能消除初始操作选择的歧义和摩擦。

**Evidence or affected scenario：** 匹配详情区域的建立/移除关系操作。由于没有截图，不能判断具体间距、颜色、按钮样式、默认动作或视觉质量；问题仅限于评审包明确陈述的邻接和等权关系。

**Recommendation：** 根据当前关系状态明确主操作与移除操作的层级和后果，让移除保持可发现但不与建立关系竞争同等主导权；继续保留确认对话框。具体采用位置、样式、菜单或其他表达，应在可见界面中比较后决定。本建议是由高信任任务和操作后果支持的重要改进，不是新视觉方向。

**How to verify：**

1. 分别截取“尚未匹配”和“已经匹配”状态，确认每个状态下的首要操作及移除后果无需试错即可辨认。
2. 用指针和键盘各走一遍确认与移除路径，核对默认动作、焦点顺序、确认对话框、取消后的焦点恢复。
3. 用 VoiceOver 检查两项操作的名称、角色、后果和确认对话框是否清楚区分。
4. 以真实对账任务做视觉验收：用户应能在不点击的情况下说出当前首要动作及哪个动作会移除已建立的关系。

## 未判定为问题的待验证风险

以下信息会影响能否完成核心任务，但当前材料只表明“未知”，不支持将其升级为 Finding：

1. **键盘闭环：** 已知 Tab 可到达列表，未知是否能选中行、建立匹配、移除匹配、操作对话框并恢复焦点。
2. **VoiceOver：** 未提供名称、角色、值、匹配状态、列表分组、阅读顺序、操作结果或对话框焦点证据。
3. **窗口适配：** 三栏在所有宽度保持等宽是实施观察，但没有最小窗口尺寸、真实内容或截图，尚不能声称出现截断、遮挡或核心动作不可达。
4. **本地化：** 未提供德语或长内容；无法判断发票名、金额、日期、动作名称和状态文案的扩展表现。
5. **恢复机制：** 已知移除操作有确认对话框，撤销行为未知；不能声称缺少撤销，也不能声称恢复已经充分。
6. **视觉工艺：** 没有截图和测量，无法评审层级、间距、排版、对比度、品牌一致性或浅绿色的实际品质。

## 支持的完成阶段

- **本评审交付物：** 已完成 UI Review 契约下的证据边界、严重级别排序、验证方法和验收路径。
- **界面本身的最强可支持状态：** 仅有“文字化实施观察已接受评审”；不支持宣称视觉已验证、原生交互已验证、体验已验证或用户已接受。
- **明确不支持：** 不能由本材料推导 Design complete、Prototype complete、Code complete、Experience verified 或 User accepted。

## 精确验收路径

1. 使用带构建号的当前 LedgerDesk Mac App，在 macOS 14 或项目最低支持版本启动，准备包含已匹配、未匹配、长发票名、大额金额与相近发票信息的代表性数据。
2. 在默认窗口中先走指针路径：选择到账款与发票、确认匹配、核对状态，再移除匹配、取消一次并确认一次；记录结果和焦点去向。
3. 不使用指针，从进入界面开始完成相同闭环：到达三栏、选择行、查看匹配详情、确认、移除、操作确认对话框、取消并恢复；录制可见焦点。
4. 开启 VoiceOver 重走核心路径，检查三栏分组、行名称与金额、选中状态、匹配状态、两个动作的后果、对话框焦点和操作后状态。
5. 在最小、默认和展开窗口分别检查三栏内容、选择上下文、详情信息和关键操作是否清楚且可达；保存各状态截图与缩放录屏。
6. 切换德语或用等效长文本、长金额/日期重新执行窗口检查，记录截断、换行、遮挡和操作可达性。
7. 对已匹配、未匹配、选中及聚焦状态做实际对比度测量；同时确认匹配状态无需颜色也可理解。
8. 检查移除后的恢复路径：若支持撤销，验证命令、反馈和恢复结果；若不支持，确认对话框是否充分表达后果，并把该产品决定记录下来。
9. 只有在上述证据中确认两个 Finding 已解决，且键盘、VoiceOver、窗口与恢复路径均完成后，才能将相应范围报告为 **Experience verified**；最终视觉和真实使用结果仍需用户确认后才能称为 **User accepted**。
