# Public Interface First-Use Checks — 2026-07-31

## Method

Three independent, no-history agents received one public starter prompt plus a bounded product brief. They were not given expected assertions, prior task context, or the other agents' outputs. The runs were response-only and made no repository changes.

These checks evaluate whether a first-time user can understand and enter the intended public workflow. They do not prove how Codex renders the Plugin card, whether the icon is visually accepted, or whether any resulting product experience is natively verified.

## Starter Prompts Exercised

### `public-direction-first-use`

> Use `$apple-ui-direction` to define a visible iPad product direction from this brief, including the key screen, interaction intent, and evidence boundary. Brief: FieldNote helps researchers take quick notes, tag moments, and review them after an interview. Hardware keyboard and touch are used together, and switching must not lose input.

### `public-adaptation-first-use`

> Use `$apple-platform-adaptation` to translate this established iPhone experience to iPad and Mac, separating shared product DNA from platform-specific hierarchy and input. Brief: a single-track audio editor with waveform, play/pause, seek, trim, undo, and export; iPhone currently uses a full-screen waveform and bottom trim sheet.

### `public-review-first-use`

> Use `$apple-ui-review` to review this macOS interface against product intent, prioritize only evidence-backed findings, and name the remaining validation gaps. Product intent: safely match an incoming payment to the correct invoice. Evidence: a matched row uses only pale green; Confirm Match and Remove Match are adjacent with equal visual weight; no screenshot or runtime access is available.
