## Environment Limit Found

The iOS 17.5 Simulator Accessibility settings expose Display & Text Size, Motion, Spoken Content, Touch, Face ID & Attention, Nearby Device Control, Keyboard, Captions, and Live Speech, but no operable VoiceOver entry. Directly writing `VoiceOverTouchEnabled`, `AccessibilityEnabled`, and `ApplicationAccessibilityEnabled` did not start VoiceOver focus or speech, so those preference values are not accepted as runtime evidence.

Apple's current `XCUIVoiceOverService` page was checked on 2026-07-30. It publishes programmatic VoiceOver control as Beta for iOS, iPadOS, and macOS 27.0+, while this machine has iOS 17.5 and 26.5 Simulator runtimes. The API therefore cannot close the represented runtime gap.

## Supported Completion

The example supports `semantics-checked` and `Reduce-Motion-experience-verified` for the named Stillpoint task on the recorded iOS 17.5 simulator. It does not support `VoiceOver-experience-verified` or a broad accessibility completion claim.

## Project Completion Decision - 2026-07-31

The product owner chose not to make a live VoiceOver or other assistive-technology run a closure condition for the Issue #7 method work. Issue #7 may close based on the maintained method, current Apple sources, deterministic regression suite, semantic audit, and recorded Reduce Motion task evidence.

This is a scope decision, not new runtime evidence. VoiceOver remains unverified for this interface, and no broad accessibility completion claim is supported. Before any future `VoiceOver-experience-verified` or broader assistive-technology claim, complete one named end-to-end path on a supported physical device or real Mac and preserve:

1. build, OS, device, and technology;
2. entry, discovery, operation, error or interruption, recovery, and completion;
3. recording or equivalent raw evidence;
4. observed speech, focus, action, and task result;
5. remaining untested technologies and locales.
