# FieldNote · 一条摘录的浏览器原型

主要交付约定：Screen or Flow。沿用用户确认的“安静、文字优先”，仅覆盖一条摘录的输入 → 保存 → 失败重试 → 卡片 → 底部编辑 → 保存。目标产品为 iPhone 本地工具；此交付是普通 HTML/CSS/JS 浏览器原型，不是 iOS 原生实现。

## 入口与数据边界

打开 `index.html`，无需安装依赖。也可在此目录运行 `python3 -m http.server 8766` 后访问 `http://127.0.0.1:8766/`。浏览器由主代理检查。

保存使用当前浏览器的 localStorage，专用键为 `fieldnote.direction.v1`，没有网络请求。只有写入成功才显示已保存。失败演示由侧栏“下一次保存失败”控制；真实浏览器存储不可用也会进入失败状态。浏览器数据不是 iPhone 文件或数据库，也不是生产持久化验证。未保存的输入在当前页面会话中保留；刷新仅恢复已保存版本。

## 已确认范围与设计判断

- 用户决定：纸书读者、文字优先、今天整理一条摘录、没有云端/账号/商业化，不探索品牌方向。
- 核心完成条件：书名与摘录都有内容；保存成功后出现内容完整的摘录卡片和文字确认。卡片是再次编辑的明确入口。
- 恢复要求：保存失败时保留所有输入；重试保存当前输入；编辑失败不替换原已保存卡片。
- 本原型的可逆设计判断：取消编辑称为“返回”，保留这次输入；卡片以“有修改尚未保存”提示，再点可继续。成功后更新同一张卡片，不新增第二条。
- 字体使用本机系统字体与中文衬线后备；纸白表面、墨色文字、单一深色保存按钮。颜色、字号、间距和动效时长属于等待浏览器与用户视觉确认的提议，不是已批准设计值。

## 状态与转移

```text
空表单 → 输入 → 点击保存 → 校验
  空内容 → 字段错误 → 修正 → 再保存
  有效内容 → 保存中 → 成功 → 摘录卡片
                    → 失败（输入不变）→ 重试 → 成功
摘录卡片 → 底部编辑面板 → 修改 → 保存 → 更新同一卡片
                        → 失败 → 保留修改 → 重试
                        → 返回 → 原卡片＋未保存提示 → 再次进入
```

## 底部编辑面板与动效

“从底下出来一层”在本流程称为 **底部编辑面板 / bottom sheet**。它承载一段暂时、聚焦的编辑任务，背景保留原摘录卡片；不是跟随某个按钮定位的 popover。本术语描述行为，不指定 Apple API 或版本。

点击卡片时面板从底部短距离上移，背景降低强调：说明“正在编辑这张卡片”，不把用户带到另一段导航。返回或保存成功后面板退下，焦点回到卡片；失败保持面板与输入位置，不用摇晃或移动错误。没有弹跳、庆祝、强制等待或只能拖动关闭的操作。普通表达为 220ms 的面板入场、160ms 的退场；这些仅是原型提议。系统减少动态效果或侧栏演示开关启用后改为短淡入淡出，继续保留标题、错误和保存文字反馈。

交互覆盖鼠标/触摸点击、表单键盘输入、可见按钮、Escape 返回及面板焦点循环。这里实现的是浏览器语义与焦点设计，不能等同于 iPhone 触摸、软键盘、VoiceOver 或原生 sheet 动效验证。

## 按步骤验收

1. 清空演示或首次打开后，在书名输入“山中的一天”，在摘录输入“慢下来，才能看见沿途细小的变化。”。
2. 点击“保存摘录”。预期出现“已保存到此浏览器”和同一份完整内容的卡片。
3. 先在侧栏勾选“下一次保存失败”，再点卡片的“编辑摘录”区域。预期底部出现标题为“编辑摘录”的面板，原卡片仍在背景，输入与已保存内容一致。编辑面板是模态区域，打开后不会操作背景侧栏。
4. 修改书名或摘录，点击“保存修改”。预期面板保留，看到失败说明、“重试保存”和原输入；背景卡片仍是上一次保存内容。
5. 点击“重试保存”。预期同一张卡片更新、面板关闭，看到保存成功文字，没有重复新增。
6. 再打开编辑，修改后点击“返回”。预期已保存卡片不变，有未保存修改提示；再次点卡片可继续同一份修改。
7. 初始空表单直接保存，预期分别说明缺少书名/摘录并将焦点送到第一个缺少项。输入纠正后可继续。
8. 启用“减少动态效果”后重复打开、返回、失败重试；预期保留任务反馈，面板不做空间滑动。用 Tab、Shift+Tab、Escape 检查可达性与焦点返回；在窄屏和长中文内容下检查保存按钮可达。

“清空演示”只清除这个原型的专用浏览器记录，不属于 FieldNote 产品流程。
